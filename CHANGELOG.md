# Changelog

All notable changes to **motion-work/statamic-ai-assistant** are documented here.

## Unreleased

**Upgrading:** republish config and assets after updating (`php artisan vendor:publish --tag=statamic-ai-assistant-config --force` and `--tag=statamic-ai-assistant --force`). Sites that only set Infomaniak credentials keep working unchanged.

### Removed

- **Groq provider (breaking):** `GroqService`, the `groq_api_key`, `groq_model` and `groq_http_timeout` config keys, and the `lucianotonet/groq-laravel` dependency are gone. A site still set to `STATAMIC_AI_ASSISTANT_PROVIDER_NAME=groq` falls back to `auto`: OpenRouter when `OPENROUTER_API_KEY` is set, otherwise Infomaniak; with neither key, the AI features are hidden. Groq's models are available through OpenRouter.

### Added

- **Service accounts for the connector:** with `STATAMIC_AI_ASSISTANT_MCP_SERVICE_TOKENS=true`, `/mcp` also accepts long-lived bearer tokens (`sai_svc_…`) minted with `php artisan statamic-ai-assistant:service-token {email} --name=…` (`--revoke`, `--plain`). A token acts as its Control Panel user with the same role, Claude level and policies; only its hash is stored (`mcp_service_tokens_path`, default `storage/app/statamic-ai-assistant/service-tokens.yaml`). Off by default, so existing installs are unchanged. New MCP tools: `list_blocks` (block catalog with hints, read level, everyone), and for service accounts only `write_site_instructions`, `set_style_rules` and `install_package` (edit level, saved without a preview). `install_package` runs a package's installer registered with `PackageInstallers` or its `mateo-package:install` command. While service tokens are on, the AI instructions page shows without an AI key. New config `mcp_service_tokens`, `mcp_service_tokens_path`, `mateo_control_plane_url` (optional, unused). See `docs/service-accounts.md`.
- **Connector tool hints (ChatGPT):** `tools/list` marks each connector tool as read-only, additive or destructive (MCP `annotations`). ChatGPT, which connects once `chatgpt.com` is in `STATAMIC_AI_ASSISTANT_MCP_REDIRECT_HOSTS`, then asks for confirmation only on saves, not on every read and preview.
- **Free models only (OpenRouter):** a super-admin switch on **Who has access** runs every text task and semantic search on OpenRouter's free models. The addon ranks the free models by OpenRouter's intelligence order and picks per task (reliable tool calls and a large context for the agent, image input for image analysis, models that can skip reasoning for quick tasks), sending the best two plus `openrouter/free` as the last fallback, and moves busy or blocked models down for a while. An optional second switch allows models that use prompts for training (needed by many free models and every free embedding model). Image generation, web search and presets are off in free mode (OpenRouter bills searches and images even with free models), so the composer hides the web search toggle; editors get plain hints when the free models are busy or the daily limit is reached. The card shows the free model each task uses and today's free requests. New config `openrouter_free_models` (`STATAMIC_AI_ASSISTANT_OPENROUTER_FREE_MODELS`, `…_ALLOW_TRAINING`, and tuning keys).
- **AI agent moves entries in page trees:** a new `move_entry` tool places an existing entry of a structured collection under another parent, at the top level, or after a given sibling ("verschiebe diese FAQ in die Gruppe …"). It checks the tree's depth limit and root page, refuses moving an entry under itself or its own children, and needs the editor's rights to edit the entry and reorder the collection (super admins always). The planner's catalog now marks structured collections with their depth limit and shows each shortlisted entry's parent; `read_entry` reports the parent too. The Claude connector's compose save uses the same tree placement.
- **AI agent saves new entries as drafts:** a new entry the agent generates is saved in Statamic as an unpublished draft right away, in the queued job, for the CP user who sent the message and only when they may create entries in that collection and site. When a run creates one entry, the CP opens it behind the agent, and the chat shows “I created the draft …” with **Minimise & view** and **Open in Control Panel**. Updates and translations keep the preview and confirmation. New config `auto_save_new_entries` (`STATAMIC_AI_ASSISTANT_AUTO_SAVE_NEW_ENTRIES`, default `true`).
- **Minimise the AI agent:** a **Minimise** button in the agent's top bar hides the full-screen view without touching the chat; a small **Back to the AI agent** button next to the launcher reopens it.
- **OpenRouter provider:** one API for every model. Set `OPENROUTER_API_KEY` and the addon uses OpenRouter automatically: `provider_name` now defaults to `auto` (OpenRouter when its key is set, Infomaniak otherwise); `openrouter` and `infomaniak` still pick one explicitly. Requests carry the site's `APP_URL` and title (`OPENROUTER_APP_TITLE`), and a hash of the CP user id (never the id itself), including in queued agent and translation jobs. New config: `openrouter_api_key`, `openrouter_base_url` (`OPENROUTER_BASE_URL`; EU in-region routing on OpenRouter Business/Enterprise via `https://eu.openrouter.ai/api/v1`), `openrouter_app_title`, `openrouter_http_timeout`, `openrouter_profiles`, `openrouter_provider`.
- **Models per task:** every AI call runs as one of five tasks, each with its own ordered model list (first answers, the rest are fallbacks), reasoning effort and optional OpenRouter preset: `agent` (planning and entry generation), `light` (quick helpers, the former fast tier), `field` (Ai Text / Bard buttons), `translate` (LLM translation fallback), `vision` (alt text, image analysis). Override per task with `OPENROUTER_<TASK>_MODELS`, `_REASONING` and `_PRESET`. With a preset, models can be changed for every site in the OpenRouter dashboard. Infomaniak maps the tasks onto its existing models.
- **Privacy defaults for OpenRouter:** only providers that do not collect prompts are used (`OPENROUTER_DATA_COLLECTION=deny`). `OPENROUTER_ZDR`, `OPENROUTER_PROVIDER_ONLY`, `OPENROUTER_PROVIDER_IGNORE` and `OPENROUTER_PROVIDER_SORT` narrow routing further. Use Infomaniak when a client needs Swiss hosting.
- **AI usage page** (super admins): cost, calls and tokens per month, by task, model and person, the fallback rate, the latest 50 calls, and the OpenRouter key's spending limit, what remains and when it resets. Every AI call is logged as one JSON line in `storage/app/statamic-ai-assistant/usage/<YYYY-MM>.jsonl` with the CP user id, task, model, tokens and cost; prompts and replies are never stored. Cost is only reported by OpenRouter. New config `usage_tracking` (`STATAMIC_AI_ASSISTANT_USAGE_TRACKING`, default `true`), `usage_retention_months` (default `12`), `usage_path`.
- **Structured outputs for the AI agent (OpenRouter):** entry generation sends a JSON Schema built from the blueprint, so models return valid entry JSON far more often; the JSON repair retry stays as a safety net. A rejected schema is logged and the call repeats once without it, so a schema problem never fails a generation; blueprints nested deeper than 6 levels get no schema. Such requests send no `temperature` (OpenRouter would otherwise find no provider). New config `openrouter_structured_outputs` (`OPENROUTER_STRUCTURED_OUTPUTS`, default `true`).
- **Prompt caching for the AI agent (OpenRouter):** the agent session id is sent as `session_id`, and Anthropic models get `cache_control`, so repeated turns hit the provider's cache (cached input ≈0.1× on Anthropic, 0.25–0.5× on OpenAI; Anthropic's first write 1.25×). New config `openrouter_prompt_caching` (`OPENROUTER_PROMPT_CACHING`, default `true`).
- **Web search for the AI agent (OpenRouter):** a **Web search** button in the agent's composer lets editors switch it on per message (off by default; it stays on for the follow-ups of that chat). The agent searches when it needs current or external facts, its sources appear as links under the reply (and in “copy conversation”), and it may open the pages it cited. Images are still only saved from pages the editor provided. Not offered on Infomaniak or OpenRouter's regional hosts. Search queries go to the search provider and are not covered by zero data retention; each search costs about $0.007–0.015, and the AI usage page counts them. New config `web_search` (`STATAMIC_AI_ASSISTANT_WEB_SEARCH`, `_ENGINE`, `_MAX_RESULTS`, `_MAX_TOTAL_RESULTS`, `_ALLOWED_DOMAINS`, `_EXCLUDED_DOMAINS`).
- **Image generation for the AI agent (OpenRouter):** the agent can create an image with an image model when an editor explicitly asks for one, and sets it on the entry's image field (new entries and updates). It never generates images to fill empty fields on its own. Off until a super admin switches it on under **Who has access → Image generation**; `STATAMIC_AI_ASSISTANT_IMAGE_GENERATION` overrides that switch. Images are saved as assets in an `ai-generated` folder of the entry's image container, labelled `ai_generated: true` with the prompt in `ai_prompt`, with an alt text from the vision model; images of a discarded preview stay in that folder. Models in the new `image` profile (`OPENROUTER_IMAGE_MODELS`, default FLUX 3 Klein at about $0.009 per image, then Gemini 3.1 Flash Image at about $0.07), tried in order by the addon. Costs appear on the AI usage page. New config `image_generation` (`_FOLDER`, `_MAX_PER_ENTRY` = 4, `_ASPECT_RATIO`, `_RESOLUTION`, `_FORMAT`).
- **Semantic search for the AI agent and the Claude connector (OpenRouter):** entries are found by meaning as well as by words, in the agent's `find_entries`, `search_entry_content` and read lookups and in the connector's `find_entries`; an exact title or slug match stays first, and the connector's semantic matches pass the same `view` check. Build the index once with `php artisan statamic-ai-assistant:embeddings build` (or **Rebuild index** on the AI usage page); saving or deleting an entry then updates it on the queue. Everything falls back to the existing keyword search while semantic search cannot run (other provider or no key, switched off, no index yet, index from another model, too many entries, failed request). New `embedding` profile (`OPENROUTER_EMBEDDING_MODEL` = `openai/text-embedding-3-small`, `OPENROUTER_EMBEDDING_DIMENSIONS` = 512, about $0.02 per million tokens) and config `semantic_search` (`STATAMIC_AI_ASSISTANT_SEMANTIC_SEARCH`, `_PATH`, `_QUEUE`, `_MAX_ENTRIES` = 5000, `_MIN_SIMILARITY` = 0.3). The index lives in `storage/app/statamic-ai-assistant/embeddings/`. Entry text and queries are sent to the embedding provider.
- **For developers:** an `AiCompletionFinished` event after every successful AI call (provider, task, requested and used model, generation id, usage incl. cost, duration, context), and scoped helpers on `AbstractAiService`: `forTask()`, `withRequestOptions()`, `withCompletionContext()`. All providers share one OpenAI-compatible HTTP client.
- **Claude app connector:** every install exposes `{APP_URL}/mcp`. Any Control Panel account can sign in, whatever its email domain. An address that is not a Control Panel account is refused. Claude translates with its own account. Saves are committed through Statamic git automation when that is enabled.
- **Edit entries from the Claude app:** two new connector tools, `preview_entry_edit` and `save_entry_edit`, change the text of an existing entry in place, in any language. The signed-in account's Control Panel role decides which entries it may edit (for example the Editor role). Claude shows each changed text before and after and saves only after the user agrees. Untouched text and the published state stay as they were. Besides text, Claude can change toggles, choice fields (select, button group, radio, checkboxes) and links, at the top of the entry and inside replicator, grid and component blocks; each is listed with its label and location ("Komponenten › tiles 2 › Kacheln › row 1"), a choice must be one of the field's options, and a link must be a URL, `mailto:`, `tel:`, a `/path`, a `#anchor` or `entry::<id>` of an existing entry. The slug changes only when Claude passes a new one: it is formatted like the Control Panel slug field, a slug another entry in the same collection and site already has is refused, and the preview warns that the web address changes. The save fires Statamic's normal events and records the account as `updated_by`. If the entry changed after the preview, nothing is saved.
- **Compose and refactor entries from the Claude app:** `get_content_model` gives Claude the same brief the AI agent works from (every field and content block with the editors' block hints from the AI block hints page, site instructions, glossary and style rules), so it can build a new entry from a goal and the user's content, or restructure an existing one. `preview_compose_entry` maps the composed JSON with the agent's own mapping, validates it against the blueprint (a missing required field is reported, not filled with a placeholder) and returns an outline; `save_compose_entry` saves after the user agrees. New entries are unpublished and placed in the page tree (optionally under a parent); a refactor goes in place or into an unpublished copy, as the user chooses. Blocks sent back with their stored id are kept exactly as stored apart from the fields Claude changed, so images, entry references and a disabled state survive. A library image only fills a required image field left empty. Creating needs the collection's create permission, in place the edit permission.
- **Images from the Claude app:** Claude can replace an image on a page or put one into an empty image field, at the top of an entry or inside a block, for example with a picture the user attached in the chat. `prepare_image_upload` returns a one-time upload link (30 minutes, one image, JPG/PNG/GIF/WebP/AVIF/SVG up to `image_fetch.max_bytes`) because Claude cannot pass attachments to a connector: the user opens it and drops the image, or Claude posts it with curl when it can. The image goes into the container and folder Claude names, with the alt text Claude writes; an existing file is never overwritten. It needs the role's “Upload assets” permission for that container, checked when the link is made and on upload. `check_image_upload` returns the stored path, which Claude sets through `preview_entry_edit` / `save_entry_edit` like any other value: assets fields are now listed there as kind `asset` with their container and folder, and take only assets that exist in that container (and folder, when the field is restricted). Block locations now include each block's heading (`Komponenten › tiles 4 › Kacheln › row 2 "Bankkaution"`), so Claude finds the section the user names.
- **Claude access per role and user:** the super-admin page “AI agent access” is now **AI & Claude access** and is shown even without AI features. Its first card, **Claude app**, chooses between “Same as the Control Panel” and “Set per role and user”. In the second mode each role gets one level for the Claude app, independent of what it may do in the Control Panel: *no access*, *read*, *edit* (also translate, compose, duplicate, upload images, change the glossary) or *publish*. A user gets the highest level of their roles, unless the user has a level of their own, which wins even when it is lower. Tools above the level are hidden and refused, and an account without a level cannot sign in. The Control Panel role still applies on top. Off by default, so nothing changes until a super admin turns it on. Stored in `access.yaml` (`claude_restricted`, `claude_none`, `claude_read`, `claude_edit`, `claude_publish`).
- **Browse the asset library from the Claude app:** `list_assets` lists the files (path, type, size, alt text) and subfolders of a folder, or searches file names below it. It needs the role's “View assets” permission for the container, as in the Control Panel.
- **Alt text for library images from the Claude app:** `review_images` shows batches of images with inline JPEG previews, the asset blueprint's locale→handle map (`alt`, `alt_fr`, …), current meta and a copy brief — Claude writes the alt strings itself (the CMS never calls Infomaniak or DeepL). `preview_asset_alts` / `save_asset_alts` follow the usual confirmation token. Scope `missing` (default) skips assets that already have every requested handle filled.
- **Fewer tokens for the Claude app:** tool results are compact JSON instead of pretty-printed (30–40% smaller). The composing brief now comes in two steps: `get_content_model` carries the block catalog with every description and when-to-use rule but no block fields, and the new `get_block_schemas` returns the fields of the blocks Claude chose (a refactor gets the fields of the blocks already on the page). Field descriptions repeated across fields are written once as numbered notes. Composing a typical page drops from about 80,000 to under 40,000 characters.
- **Link fields accept anchors, `mailto:` and `tel:`** in AI agent output, as the link fieldtype does.
- **Duplicate, publish and unpublish from the Claude app:** `duplicate_entry` runs Statamic's own Duplicate action as the signed-in account (an unpublished copy with "(Duplicated)" and a new slug, in the same place in the page tree, plus the localizations the account may create); it needs the collection's create permission on that site. `set_published` publishes or unpublishes one entry in one language and needs the publish permission. Both describe the change first and act only with `confirmed: true`.
- **Claude connector follows the Control Panel role:** entries are listed and read only when the account may view them, and a localization is saved only when the account may edit it, including access to the target site. A preview can only be confirmed by the account that made it.
- **Translations survive a deploy:** entry translations are saved quietly (so relationship sync does not rewrite the source), then queued for Statamic git when git automation is on. Linked localizations from the same run share that one commit.
- **AI translation fallback:** without `DEEPL_API_KEY`, every translation path (field/Bard, Translate entry action, bulk, terms, navigation) runs on the configured AI model instead of failing with "DeepL API key is not configured". Editors are told each time: an info toast after field/Bard translations, a note in the entry action message (whose label becomes "Translate (AI)"), and an info card on the bulk translations page. Glossary terms that occur in the text and per-language style rules are passed to the model; HTML (Bard) markup is preserved; Swiss German targets use "ss" instead of "ß". New config `translation_llm_fallback` (`STATAMIC_AI_ASSISTANT_TRANSLATION_LLM_FALLBACK`, default `true`).

### Fixed

- **Moving an entry into a group no longer fails:** the agent turned it into a field update, which has nothing to change because the parent lives in the collection tree, and the empty reply `{}` was then rejected as "an array, not an object". Moves now go through `move_entry`, and an update that changes nothing (`{}` or `[]`) shows as "no field changes" instead of failing.
- **The agent's summary no longer claims success when an entry job failed:** once all entries of a turn are finished and one failed, the summary turn is rewritten ("1 von 2 erledigt. Nicht geklappt: «…».").
- **AI agent:** the last step of a read-only answer now reads “Answer ready.” instead of “Plan ready — no entries.”.
- **AI agent chat feels like a conversation:** while the agent works, one line shows what it is doing right now (its real steps, a running timer, and a ▸ to open the step list); finished replies keep a small “Worked for 42s ▸” line with their steps, also after a reload. Replies render Markdown (lists, headings, bold, code, links) without sender labels, get copy and “Try again” buttons, and the send button becomes a stop button while the agent works. A “jump to latest” button appears when you scroll up, and new messages fade in (off with reduced motion).
- **Errors are short hints in the chat:** failures (no connection, timeouts, an exhausted budget, an expired chat, server problems) appear as a short plain-language note in the conversation with “Try again” or “New chat”, never as raw technical messages; the raw text is still in “Copy conversation”. A lost connection shows a calm hint and polling backs off and recovers on its own. Saving failures show on the card.
- **Agent texts follow the CP language:** queued agent jobs now run in the editor's Control Panel language, so summaries (“Fertig — …”), card notes and activity lines are no longer English in a German CP.
- **Clearer card notes:** duplicates are shown once, the missing-image note is phrased plainly, and the fallback-link notes (a site setup detail) go to the log instead of the card. The content preview no longer shows “[object Object]” for media and other object values.

- **AI agent keeps a running request across page loads:** a request still running when the page reloads (or when an editor opens it from the chat history) is picked up again, so the agent shows its progress and result instead of a conversation with only the editor's message. Entry cards of a finished run now come back with their content.
- **AI agent says when a request waits for a queue worker:** after 15 seconds without a worker picking up the planning job, the agent shows that it is still waiting and that a queue worker may not be running (`php artisan queue:work`), instead of a planning animation that never ends. Progress responses carry the new `waiting_seconds` field.
- **German “Ready to review” label** on entry cards read “Bereit, den Abschnitt zu wiederholen?”; it now reads “Bereit zur Prüfung”.

- **`search_entry_content` no longer matches the blueprint handle:** once an entry was loaded from disk, its `blueprint` value was searched as text, so a query such as “page” matched every entry of that blueprint.
- **Thinking models keep their reasoning across tool calls:** the agent's tool loops sent tool-call turns back without the model's `reasoning` / `reasoning_details`, which breaks Claude and Gemini thinking models mid-run. They are now passed back unchanged.
- **Errors during a streamed answer are reported:** a provider error that arrived after streaming had started was dropped, so the answer just looked cut off. It now fails with the provider's message. An empty reply because the output budget ran out (usually on reasoning) says so.
- **Editors see why the AI refused:** running out of credits, a site's OpenRouter spending limit, no model matching the routing rules, or content moderation now show as a readable message in the agent and on the Ai Text / Bard buttons, instead of a generic error. Credit and budget errors are never retried.
- **Composing an entry keeps slug fields and existing files:** `preview_compose_entry` dropped a slug field such as `client_slug` (it was missing from the brief, and a value sent anyway was thrown away, then reported as required). It also dropped an assets path unless the file was an image inside the field's starting folder, so a gallery image stored at the container root and a GLB model both came back as empty. A path is now kept when the file exists in the container; the folder limits it only when the field is restricted to that folder. A missing file is named in the warnings. `prepare_image_upload` accepts every file type the container allows, including GLB, not only images.
- **No localizations in sites a collection does not have:** translating into a site the entry's collection is not enabled for (the Translate action, bulk, the AI agent's localize step or the Claude connector) wrote the localization's file and then failed in Statamic for structured collections, leaving an entry the Control Panel does not show. It is now refused with a message saying to add the site to the collection first.
- **Queued bulk translations report every page:** parallel queue workers wrote their status rows into one shared list at the same time, so a page could vanish from the progress list and from the final counts, and the progress bar jumped back and forth as each job wrote its own position. Rows are now written under a lock, the bar counts the jobs Laravel's job batch has finished, and the line under the bar names the page that started most recently. Needs a cache store with locks (database, redis, file), as the AI agent already does.
- **Translated links after a deleted localization:** a queue worker reused the linked-entry ids it had resolved in earlier jobs, so after a localization was deleted and translated again, later translations could still link to the deleted entry. Each translation and reconcile run now starts with a fresh reference cache.
- **Connector sign-in only reaches allowed apps:** client registration accepted any HTTPS callback, and the sign-in page did not say where it would send the user, so a stranger could register a client pointing at their own server and collect a Control Panel account's access from a link. Callbacks must now be on a host in the new `mcp_redirect_hosts` config (`STATAMIC_AI_ASSISTANT_MCP_REDIRECT_HOSTS`, default `claude.ai,claude.com`; `localhost` always allowed), checked at registration and again at every sign-in, and the sign-in page names the host. Clients that register for `client_secret_post` / `client_secret_basic` get a secret that is now required at the token endpoint; public clients (what the Claude app uses) get none and rely on PKCE as before. HTTP Basic client authentication now also reads the client id from the header.
- **Connector sign-ins can survive a deploy:** new config `mcp_cache_store` (`STATAMIC_AI_ASSISTANT_MCP_CACHE_STORE`, default: the default cache store) keeps connected apps and their tokens in a store of their own. Point it at a store the deploy's `cache:clear` does not empty, for example `database`, so nobody has to sign in to the connector again after each deploy.
- **Re-translating keeps the page's address:** updating an existing localization (DeepL, the AI fallback or the Claude connector) no longer replaces its slug with one made from the new translated title, which could change a live URL. A new localization still gets its slug from the translated title.
- **Stale translations are refused:** `save_localization` refuses with `entry_changed` when the source entry changed after `preview_localization`, as `save_entry_edit` already did.
- **Numbers survive translations:** translating an entry no longer overwrites Bard heading levels and integer fields whose value matched a text's position (a level-2 heading could become the text of the second segment). This affected DeepL, the AI fallback and the Claude connector.

### Changed

- **Changing the glossary and style rules needs a role permission:** new Statamic permission “Edit translation glossary and style rules” (`edit translation glossary`, under Users → Roles, group “AI Assistant”). Every Control Panel user can still read them; without the permission the page is read-only and the Claude connector's `save_glossary` and `save_style_rules` refuse. Super admins always may. Grant it to the roles that maintain terminology (for example Editor) after upgrading, since they apply to every translation on the site.

- **Queued AI jobs record who started them:** the planning, entry generation and translation jobs store the dispatching CP user, for the usage log and OpenRouter attribution. Jobs queued before the upgrade still run.
- **German sidebar label:** “Massenübersetzungen” is now “Übersetzungen”.
- **AI features need the active provider's key:** without it (`OPENROUTER_API_KEY` or `INFOMANIAK_API_TOKEN`, depending on the provider) the agent, field buttons, AI instructions and agent access are hidden. Translation UI stays only when `DEEPL_API_KEY` is set, or when the token is set and the LLM translation fallback is on. The **Glossary & style rules** page is the exception: it is always shown (unless `STATAMIC_AI_ASSISTANT_TRANSLATIONS=false`), because Claude follows them through the connector even without DeepL or an AI model.
- **AI agent localizes instead of duplicating:** asking the agent to translate an existing entry (for example “übersetze diese Seite auf English” / “erstelle den EN-Eintrag”) localizes that source entry onto the target site and translates it there. It no longer creates a separate entry on the site that is open in the Control Panel.
- **Quick tasks skip reasoning:** Ai Text / Bard generate and refactor, alt text, image analysis and fast-tier helpers now ask Infomaniak reasoning models (Kimi K2.6, Qwen3.5/3.8) to answer without thinking first (≈0.5–3s instead of ≈13–16s, and no more empty replies when `max_tokens` runs out during thinking). The AI agent's planning and entry generation keep thinking on. New config `quick_tasks_without_thinking` (`STATAMIC_AI_ASSISTANT_QUICK_TASKS_WITHOUT_THINKING`, default `true`). Mistral models are skipped automatically, since they reject the switch.
- **Planner without URL tool:** uses `entry_generator_planner_max_output_tokens` instead of a fixed 1024 tokens, so reasoning models no longer fall back to a single entry.
- **Internal restructuring, no behaviour change:** the larger services (connector bridge, planner, entry generator, translation service and translator, batch runner, schema builder, navigation sync, DeepL wrapper) are split into focused classes, and most services are now autowired by the container. Extensions that subclass or replace an internal service should check the new class names in `CLAUDE.md`. Development: `composer check` (Pint, Sloppy, PHPUnit) runs in CI.

## 3.0.0 — 2026-07-06

Major release with CP, DeepL, and AI agent changes. **Review the upgrade steps below before updating from 2.x.**

### Added

- **AI agent** floating CP launcher with queued multi-entry generation (planner + background jobs).
- **AI agent settings** CP page: per-block hints and per-blueprint-field hints (hero, lead, …).
- **DeepL glossary & style rules** CP page (all CP users): YAML-backed term table + per-language style instructions synced to DeepL v3.
- Glossary/style **segment splitting** so glossary terms are hard-enforced even when a style rule is active (`prefer_glossary_over_style`, default `true`).
- **`ENABLE_AGENT_FOR_EDITORS`**: hide the AI agent from non-super editors while super admins always keep access.
- **`EDITOR_LIMIT_ENTRIES`**: cap non-super users to one entry per agent request (config `editor_limit_entries`).
- Style rules stored as an **array of instructions per language** in `translation-style-rules.yaml` (legacy single-string values are normalized on read).
- DeepL style-rule **reconcile-by-name** sync (cleans duplicate/orphan rules on the account).

### Changed

- **Website migration mode removed** from the CP (routes, nav, and migration UI). Use the AI agent URL-copy flow instead.
- **Bulk translations** and **AI agent settings** nav items are **super-admin only**. Glossary & style rules remain visible to all CP users.
- **`entryGeneratorEnabled`** and related CP script vars are resolved **per request** (closures), not at application boot — fixes role-based visibility.
- Published addon assets must be refreshed with `--force` after upgrades (manifest can otherwise point at stale JS).

### Breaking / upgrade required

1. **Composer constraint:** require `motion-work/statamic-ai-assistant:^3.0`.
2. **Republish config** (existing files are not overwritten by default):

   ```bash
   php artisan vendor:publish --tag=statamic-ai-assistant-config --force
   ```

   New / important keys in `config/statamic-ai-assistant.php`:

   - `enable_agent_for_editors` ← `ENABLE_AGENT_FOR_EDITORS` (default `true`)
   - `translation_glossary_path`, `translation_style_rules_path`
   - `prefer_glossary_over_style`, `editor_limit_entries`, `agent_settings_nav`

   ```bash

   ```

4. **DeepL:** translation features require `DEEPL_API_KEY`. Optional glossary/style YAML under `content/statamic-ai-assistant/` (created on first save from the CP).

5. **Style rules YAML:** if you had a single string per language under `rules.{lang}.instructions`, it still loads — but saving from the CP writes an array. Empty instructions delete the rule on DeepL.

6. **Multi-tenant DeepL accounts:** glossaries and style rules are namespaced by `APP_NAME`. Use a **unique `APP_NAME` per client** on shared DeepL accounts to avoid cross-site style-rule reconciliation.
